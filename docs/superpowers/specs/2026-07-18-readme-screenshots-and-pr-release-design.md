# InsightCut README、界面截图与 PR 发布设计

## 目标

在现有模型配置、双 TTS Provider、音色试听和 MiMo 声音克隆功能已经完成的基础上，整理一套与当前产品一致的远端项目介绍，并通过 Pull Request 合并到默认分支。

这次整理需要同时解决三个问题：

1. 根目录 README 仍包含 Vue 3 等过期信息，未能准确说明当前 React 19 前端和新的模型配置能力。
2. 仓库中的设置页截图早于服务商目录、模型选择器和配音配置改造，无法代表当前界面。
3. 新用户缺少从启动服务、填写配置、选择模型和音色，到完成试听、声音克隆与视频生成的连贯使用说明。

最终资料应像项目维护者在向真实使用者介绍产品：说明它解决什么问题、哪些地方已经可用、如何完成第一次生成，也坦诚标注本地优先、凭证自备和声音授权等边界。文案不使用空泛口号、模板化赞美或虚构数据。

本次工作是整理和补全，不是推倒重写。原 README 中已经形成的产品判断、真实生成视频示例、在线 Showcase、可恢复资产和可编辑导出等内容继续保留；只修正过期事实、调整阅读结构，并让每一项主张更容易由截图、视频或实际工作流验证。

## 发布方式

所有资料改动继续放在 `codex/llm-provider-catalog` 分支，与本次模型配置功能保持在同一个 PR 中。流程为：

1. 更新 README、使用说明和真实界面截图。
2. 完成文档检查、前后端测试、前端构建和浏览器页面复核。
3. 推送功能分支并创建面向默认分支的 PR。
4. 检查 PR diff、远端状态和可合并性。
5. 合并 PR；成功后确认默认分支包含目标提交。

不直接把未经 PR 检查的本地提交推向默认分支，也不在发布过程中改写用户主工作区里尚未提交的文件。

## README 信息架构

根目录 README 采用“先理解产品，再开始使用，最后查细节”的阅读顺序：

### 1. 产品开场

- 用简短中文说明 InsightCut 是什么、适合谁，以及它和普通一键成片工具的差别。
- 保留英文检索信息，但不让英文段落打断中文用户的阅读路径。
- 首图使用当前真实文稿工作台截图。

### 2. 当前能力

- 文稿或主题输入。
- 分镜、图片、配音、字幕与基础动态生成。
- 分段编辑、单项重新生成和失败资产保留。
- MP4 与剪映 / CapCut 草稿导出。
- 本地 SQLite 和本地媒体目录。
- LiteLLM 生文服务商选择、账号模型同步与自定义兼容接口。
- Agnes 生图、豆包 TTS、MiMo TTS、音色试听与 MiMo 声音克隆。

这一部分只描述仓库中已经落地的行为，不把规划中的能力写成已完成。

### 3. 设计理念

保留并重新组织原 README 中已经成立的产品理念：

- **不是只交付一个成片文件**：脚本、分镜、图片、配音、字幕和导出文件都作为可查看的中间资产存在。
- **默认生成之后仍然能改**：用户可以逐段检查和重新生成图片或配音，而不是因为一个细节不满意就从头开始。
- **失败不等于清空**：生成中断或任务失败时，已经完成的素材继续进入素材库和预览页，用户仍能替换、修复或继续使用。
- **本地优先**：数据库、媒体、模型配置和声音克隆参考音频默认留在本机，适合个人创作、实验和排查问题。
- **交付路径不只一种**：快速发布可以使用 MP4，需要继续精修时可以导出剪映 / CapCut 草稿。

这些理念不单独写成口号，而要与后续工作流、截图、生成视频和输出文件相互印证。

### 4. 产品截图

README 保留文稿、素材库、生产配置和预览编辑器的核心截图，并增加一张新的 API 配置页截图。API 配置页截图需要展示：

- 生文服务商和模型为可选择控件；
- “验证并同步”后的模型选择体验；
- Agnes 生图保持独立；
- 豆包和 MiMo 两端配音可同时启用；
- 音色试听、常用参数和 MiMo 声音克隆入口可被用户识别。

若完整设置页过长，优先制作一张宽屏总览和一张配音区域特写，避免把长页面压缩成无法阅读的缩略图。

### 5. 真实生成视频

保留现有 `docs/showcase/` 中的真实视频、缩略图、GitHub Pages 在线预览和仓库内 MP4 备用链接。README 继续列出每个示例的输入模式、画面比例和时长，让读者能直接判断这些结果是否适合自己的创作场景。

整理时遵循以下原则：

- 不删除仍可播放的原有示例，也不把它们替换为无法验证的宣传描述。
- 不重新编码或放大视频文件，避免无意义增加仓库体积。
- 检查在线 Showcase 和仓库相对链接；如果某个链接失效，应修复链接或明确标注，而不是静默留下坏入口。
- 用简短上下文说明示例的价值：它们不仅证明可以输出视频，也证明分镜、图片、配音、字幕和草稿仍可继续修改。

### 6. 快速开始

说明运行环境、依赖安装、后端虚拟环境、FFmpeg、端口和启动顺序。命令以仓库真实目录结构为准：后端从 `api_server.py` 启动并监听 `2002`，前端在 React/Vite 项目中监听 `2001`。

快速开始必须覆盖：

1. 克隆仓库并准备后端虚拟环境。
2. 安装后端依赖和前端依赖。
3. 启动后端，再启动前端。
4. 打开配置页，完成服务连接。
5. 回到文稿页完成第一次生成。

如果仓库没有足以支持某条安装命令的依赖文件，则不猜测命令；应依据实际文件调整说明。

### 7. 模型与配音配置

生文部分说明：

- 常规用户先选择服务商，再选择或同步生文模型。
- 账号模型同步结果会过滤掉图片、ASR、TTS、VoiceClone 和 VoiceDesign 等非生文模型。
- OpenAI-compatible 与 Anthropic-compatible 自定义地址保留给高级场景。
- API Key 只保存在本地运行配置中，不应提交到 Git。

配音部分说明：

- 豆包和 MiMo 可以同时开放，`provider` 只决定新任务默认使用哪一端。
- 预置音色可以按 Provider 全选、部分选择或关闭，已开放音色均可试听。
- 任务可调整统一语速；豆包支持音量，MiMo 支持风格提示词。
- MiMo 声音克隆需要上传或录制参考音频、确认授权，并先生成成功的试听音频后才能启用。
- 克隆参考音频、试听文件和凭证均留在本地；README 不展示或上传真实用户音频。

### 8. 项目结构、测试与安全

- 技术栈更正为 React 19、React Router 7、Vite 4、FastAPI、SQLite 和 FFmpeg。
- 列出前后端测试与构建命令，便于贡献者复核。
- 说明 `.env`、`data/`、`output/`、日志、API Key 和用户声音文件不应提交。
- 保留失败资产不丢失、默认本地存储和未声明开源许可证等现实边界。

## 截图规则

截图必须来自当前运行的本地页面，不使用设计稿冒充已实现功能。

- README 产品截图统一使用 `1600 × 900` 的 16:9 桌面横屏尺寸，避免纵向长图在 GitHub 双栏中被压缩得无法阅读。
- 截图前关闭模型下拉等临时浮层，除非该图专门展示选择行为。
- 密码输入框保持掩码状态；不得通过页面脚本、开发者工具、日志或截图暴露真实 API Key、Access Token、App ID 的完整值。
- 如果 App ID 等普通输入仍属于用户账号信息，应在截图前使用安全示例值或裁掉该区域。
- 不展示本地绝对路径、真实克隆音频文件名或其他个人信息。
- 新截图存入 `design-qa-artifacts/`，使用含义明确且稳定的文件名，并在 README 中使用仓库相对路径。
- 截图完成后检查尺寸、文件大小和实际画面，避免空白、加载中、报错提示或图片损坏。

## 内容语气

中文是主要叙述语言，英文只用于项目名、协议名、技术名词和必要的检索辅助。每一段优先回答真实使用者会问的问题：

- 这个功能解决什么麻烦？
- 第一次使用应该点哪里、填什么？
- 哪些信息需要用户自己准备？
- 失败后还能保留什么？
- 哪些内容只存在本地？

避免使用“革命性”“赋能”“无缝”“一站式”等无法验证的泛化表达，也不使用大量相同句式或机械列表。可以保留产品立场，但必须由实际工作流、可编辑资产和真实导出能力支撑。

## 验证标准

### 文档与仓库检查

- README 中不存在 Vue 3、错误端口或已经失效的配置说明。
- README 所有本地图片和文档链接都能在仓库中找到。
- 原有真实生成视频、缩略图、在线 Showcase 和仓库备用 MP4 入口均被保留并完成链接检查。
- 原有“资产可编辑、失败可恢复、本地优先、MP4 与剪映草稿并行”的设计理念仍在 README 中得到清晰说明。
- 模型、TTS、预置音色、试听和声音克隆的描述与代码及 `AGENTS.md` 一致。
- 不包含真实密钥、Token、用户声音数据或本地敏感路径。
- `AGENTS.md` 与 `CLAUDE.md` 仍保持完全一致。
- `git diff --check` 通过。

### 产品与代码检查

- 后端完整测试通过。
- 前端完整测试通过。
- 前端生产构建通过。
- 浏览器复核文稿页、素材库、生产配置、预览页和 API 配置页；用于 README 的截图均与实际页面一致。
- API 配置页实际显示服务商/模型下拉指示，并且 MiMo 账号同步只呈现生文模型。

### 远端检查

- 功能分支成功推送到 `origin`。
- PR 的 base、head、标题和说明正确，diff 不包含运行时软链接、数据库、媒体、密钥或用户主工作区改动。
- 必需检查通过且 PR 可合并。
- 合并成功后，远端默认分支包含合并提交或等价的 squash/rebase 提交。
