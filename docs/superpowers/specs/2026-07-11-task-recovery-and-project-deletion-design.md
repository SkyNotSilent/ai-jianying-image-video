# InsightCut 任务恢复与项目删除设计

## 目标

本次改动解决两个相互关联的问题：

1. 任务在模型调用失败、后端重启或进程中断后，能够保留已经完成的结果，并从缺失的最小单元继续生成。
2. 项目资产页能够删除本地草稿和后端生成项目；用户二次确认后，项目记录及其专属本地素材全部删除。

后端接口基础路径、SQLite、本地媒体服务、前端路由和现有模型配置保持不变。

## 当前问题

生成任务运行在后端进程内的 daemon 线程中。离开浏览器页面不会停止任务，但后端重启会终止线程。服务启动时，长时间没有更新的任务会被直接标记为 `failed`，不会重新执行。

当前检查点粒度也不一致：图片和配音会在单项完成后保存，但脚本、分镜和图片提示词要等整个阶段完成后才统一落库。因此，任务在图片提示词阶段中断时，可能没有任何可恢复的分镜数据。

项目资产页只允许删除 localStorage 中的文稿草稿。后端已有任务删除接口，但前端没有入口，并且现有接口只删除数据库记录，不清理项目专属媒体文件。

## 状态设计

保留现有 `pending`、`processing`、`completed`、`failed` 状态，新增 `interrupted` 和内部使用的 `deleting` 状态：

- `pending`：等待后端开始执行。
- `processing`：后端当前确实存在运行中的执行线程。
- `interrupted`：执行已停止，但任务和检查点有效，可以继续生成。
- `failed`：不可自动继续的业务错误，已有素材仍然可查看和手动补齐。
- `completed`：主生成流程已经结束；个别素材失败仍通过分镜素材状态表达。
- `deleting`：用户已经确认删除，任务不再出现在项目列表；后端等待当前单次模型请求返回后自动完成记录和文件清理。

后端启动时，不再把遗留的 `pending` 或 `processing` 任务直接标记为 `failed`，而是标记为 `interrupted`。服务不会自动继续调用付费模型，用户需要在项目资产页或进度页主动点击“继续生成”。

## 检查点设计

检查点使用现有 SQLite 表，不引入新的任务队列或外部存储。

### 文稿和分镜

脚本生成完成后立即保存脚本文本、摘要和输入模式。文本分段完成后立即创建 `task_segments`，每条分镜先以空 `image_prompt`、`pending` 图片状态和 `pending` 配音状态入库。

任务恢复时优先读取已保存脚本和分镜；只有对应检查点缺失时才重新调用文本模型。

### 图片提示词

每生成一条图片提示词，立即更新对应 `task_segments.image_prompt`，同时更新阶段进度。恢复时跳过已有非空提示词，只处理缺失项。

### 图片和配音

继续沿用单项完成后立即保存的方式。恢复时：

- 已有有效文件且状态为 `completed` 的单项直接跳过。
- `pending`、`failed` 或文件已经不存在的单项重新生成。
- 重新生成成功后覆盖当前分镜引用，但保留素材历史记录的既有语义。

### 草稿和视频

当图片与配音补齐到可构建条件后，重新构建剪映草稿。已有有效 MP4 可以跳过视频合成；无效或缺失的产物重新生成。草稿和视频阶段不做文件内部断点恢复。

## 执行与并发控制

任务执行器维护当前进程内的运行任务注册表，并为每个任务提供取消标记：

- 同一任务只能有一个活动执行实例。
- 重复点击“继续生成”返回当前任务状态，不启动第二条线程。
- 删除生成中的任务时，先把任务标记为 `deleting` 并设置取消标记；执行器在阶段边界和每个分镜单项开始前检查标记。
- 已经发出的单次模型请求不能强制终止，但请求返回后不得再进入下一项；删除清理线程等待执行实例退出后自动清理记录和文件，用户不需要再次确认。
- 服务启动时会继续清理由上一次进程中断遗留的 `deleting` 任务。

继续生成使用原任务 ID，不复制项目，不改变项目创建时间。任务状态改回 `processing` 后，从数据库检查点重建 pipeline 并执行缺失项。

## API 设计

新增接口：

- `POST /ai/native/video/kepu/tasks/{task_id}/resume`
  - 允许 `interrupted`、`failed` 且存在可恢复输入的任务继续。
  - 对已经 `processing` 的任务幂等返回。
  - 对已经 `completed` 的任务返回当前状态，不重复执行。

增强现有删除接口：

- `DELETE /ai/native/video/kepu/tasks/{task_id}?delete_files=true`
  - 默认由项目资产页传入 `delete_files=true`。
  - 先把任务标记为 `deleting` 并请求执行器取消；空闲任务立即删除，运行中任务在当前单次请求返回后自动删除数据库记录和项目专属文件。
  - 返回删除的记录类型、文件数量和无法删除的文件列表。
  - 只允许删除能够证明属于该任务的路径，禁止根据未经校验的项目名称任意删除目录。

任务查询和列表接口返回 `interrupted` 状态。现有字段保持兼容。

## 文件清理边界

删除项目时清理以下内容：

- `task_segments`、`task_assets`、`task_steps`、`task_results` 和 `tasks` 中对应任务记录。
- `data/media/{task_id}/` 下的专属图片、配音、导出文件。
- 数据库中 `task_assets.path`、`task_results.draft_path` 指向且确认位于允许根目录内的文件。
- 任务专属输出目录中的图片、配音、MP4、ZIP 和剪映草稿。

为避免同名项目互删，后续生成目录使用任务 ID 作为所有权标识。对于历史上按项目名称共享目录的任务，仅删除能够从数据库记录精确归属的文件；目录中存在无法确认归属的内容时保留目录并在接口结果中报告。

本地文稿草稿仍只删除 localStorage 数据，因为它还没有后端媒体资产。

## 前端交互

### 项目资产页

所有项目卡片右上角提供菜单按钮：

- 本地草稿：选择“删除草稿”，二次确认后删除 localStorage 记录。
- 后端项目：选择“删除项目”，确认弹窗明确列出文稿、图片、配音、视频和草稿文件会被永久删除且不可恢复。
- `interrupted` 项目显示“继续生成”，点击后调用恢复接口并进入进度页。
- `processing` 项目仍显示“查看进度”；删除时由后端先安全停止任务。

删除过程中禁用确认按钮。后端接受删除请求后立即从列表移除项目；部分文件清理失败时，项目记录仍删除，并记录残留文件路径。`deleting` 任务在列表接口中不对用户展示。

### 进度页

`interrupted` 状态显示已完成步骤和分镜进度，主按钮为“继续生成”，次按钮为“查看已保存素材”。普通 `failed` 状态根据检查点是否可用决定是否显示继续按钮。

## 错误处理

- 单次模型调用继续使用供应商现有重试逻辑；重试耗尽后保存当前单项错误并使任务进入 `interrupted` 或可恢复的 `failed` 状态。
- 数据库检查点写入失败时停止继续生成，避免页面显示的进度超过实际可恢复进度。
- 恢复时发现本地文件缺失，按该单项未完成处理。
- 删除文件失败不回滚已经完成的数据库删除，但必须返回残留路径摘要并记录日志。
- 删除和恢复互斥；删除开始后，新的恢复请求返回冲突错误。

## 测试设计

### 后端单元与集成测试

- 图片提示词每完成一条即写入数据库。
- 恢复任务跳过已有提示词、有效图片和有效配音，只生成缺失项。
- 重复恢复不会创建并行执行实例。
- 服务启动时遗留的运行任务转为 `interrupted`，已保存素材不丢失。
- 删除完成后相关数据库记录全部消失。
- 删除只清理允许根目录内、可证明属于任务的文件。
- 生成中删除会先触发取消，执行器退出后不再写回数据。

### 前端测试与验收

- 后端项目卡片显示删除菜单，本地草稿删除行为保持不变。
- 删除确认文案明确，取消不改变项目，确认后列表立即更新。
- `interrupted` 项目显示继续入口，恢复成功后进入进度页。
- 恢复和删除请求进行中按钮不可重复点击。
- 1440x900、1180x900、766x1024、390x844 下菜单、弹窗和按钮均不溢出。

### 真实流程验收

创建一个短任务，在图片提示词和图片生成阶段分别中断后端，再次启动服务并继续任务。确认已完成模型结果不重复生成，缺失项补齐，最终可以进入预览和导出。随后从项目资产页删除任务，确认数据库记录和专属媒体文件均已清理。

## 非目标

- 本次不引入 Celery、Redis 服务或跨机器任务队列。
- 本次不实现自动开机续跑，避免未确认的模型费用。
- 本次不改变模型供应商配置、媒体 URL 结构或现有编辑与导出能力。
