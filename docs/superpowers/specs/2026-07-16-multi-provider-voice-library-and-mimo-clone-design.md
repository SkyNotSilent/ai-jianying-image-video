# InsightCut 多供应商音色库、试听与 MiMo 声音克隆设计

## 目标

本次改造将现有的单供应商音色下拉框升级为完整的配音管理能力：

1. 豆包与小米 MiMo 可以同时配置、同时启用，用户不需要在全局二选一。
2. 配置页管理可用音色、默认参数和试听；生产设置页与预览页可覆盖本次任务的音色、语速、音量或风格。
3. 所有预置音色和克隆音色都可以点击试听，生成结果保存在本地缓存。
4. 第一版完整支持 MiMo 本地声音克隆库；豆包远端声音复刻和官方音色动态同步不在本期范围。

现有 `voice_type` 任务字段、本地 SQLite、本地媒体服务和资产保护规则继续保留。

## 供应商与默认音色

配置页的“配音模型”改为豆包和 MiMo 两个供应商标签页。两家配置同时保存，`tts.provider` 只表示“未显式选择音色时的默认供应商”。

第一版音色数据来源固定为：

- MiMo 官方 9 个预置音色：`mimo_default/冰糖/茉莉/苏打/白桦/Mia/Chloe/Milo/Dean`。
- 本地 SQLite 中现有的 10 个豆包音色。
- 用户在本地创建的 MiMo 克隆音色。

升级后默认向创作端开放：

- MiMo：冰糖、茉莉、苏打、白桦；默认音色为冰糖。
- 豆包：爽快思思、阳光小磊；默认音色为阳光小磊。
- 系统默认供应商继承升级前的 `tts.provider`，当前运行配置继续使用 MiMo。

配置页支持按供应商、性别和语言筛选，支持全选、全不选、单个启用以及设置各供应商默认音色。第一版不展示无法工作的“同步官方音色”按钮，也不要求豆包 AK/SK。

## 统一音色库

音色在 API 和任务中使用带来源的统一 ID：

- MiMo 预置音色：`mimo:冰糖`。
- 豆包音色：`doubao:zh_female_shuangkuaisisi_moon_bigtts`。
- MiMo 克隆音色：`mimo-clone:<clone_id>`。

现有没有前缀的任务保持兼容：MiMo 官方 ID 归入 MiMo，本地数据库中已知的音色 ID 归入豆包，其余旧 ID 继续按任务创建时的旧配置解析。

`tts_voices` 扩展为预置音色目录，增加 `provider`、`language`、`source`、`capabilities_json`和 `preview_url`，唯一约束改为 `(provider, voice_id)`。迁移必须在事务中重建表并复制现有 10 条豆包数据。

克隆音色使用独立的 `tts_voice_clones` 表，不把 Base64 或音频二进制数据写入 SQLite。记录至少包含：

- `clone_id`、名称、本地参考音频路径、时长和字节数。
- `draft/ready/failed/hidden` 状态、试听路径、最近错误和启用状态。
- 授权确认状态、创建时间和更新时间。

## 预置音色试听

配置页、生产设置页和预览页共用同一个音色选择器。音色卡片展示名称、供应商、性别、语言和当前状态。点击卡片时选中并播放试听，页面内同时只允许一条音频播放。

预置音色试听按供应商、音色、模型、试听文本和参数生成缓存键，文件保存到 `data/media/_voice_previews/`。默认试听文案为“你好，这是当前音色的试听，欢迎使用 InsightCut。”。

配置页允许使用尚未保存的供应商表单进行试听；生产设置页和预览页只使用已保存配置。试听失败只显示错误，不取消已选音色，不删除旧试听。

## MiMo 声音克隆流程

配置页的 MiMo 标签增加“预置音色”和“我的克隆音色”区域。用户通过“新建克隆音色”进入创建面板：

1. 输入音色名称。
2. 上传 MP3/WAV，或使用浏览器麦克风录制。
3. 页面显示原始音频播放器、录音时长和替换/重录操作。
4. 用户必须确认已获得该声音的使用授权。
5. 参考音频先保存为 `draft`，再使用固定文案生成克隆试听。
6. 试听成功后改为 `ready`，用户可决定是否立即向创作端开放。

上传文件只接受 MP3/WAV。浏览器录音可以提交 WebM/Opus，后端统一用 FFmpeg 转换为单声道 WAV 参考文件。页面建议录制 10–30 秒清晰单人声音，但不将这个建议做成强制时长限制。

转换后的参考音频必须包含有效音轨，并且转换为 Base64 后不超过 MiMo 官方 10 MB 限制。本地文件保存到 `data/media/_voice_clones/<clone_id>/reference.wav`，克隆试听保存为同目录的 `preview.wav`。

合成时使用 `mimo-v2.5-tts-voiceclone`。后端每次请求都从本地读取参考音频，组装 `data:audio/wav;base64,...` 作为 `audio.voice`；不在数据库、配置文件或日志中持久化 DataURL。MiMo 克隆与预置音色共用风格提示、语速语义映射和音频输出解析逻辑。

克隆音色支持试听、重命名、启用/隐藏、设置为 MiMo 默认、替换参考音频和删除。替换参考音频后回到 `draft`，原试听不再视为有效，必须重新验证。

## 配音参数与任务快照

配置页保存各供应商的默认参数，生产设置页允许本次任务覆盖，预览页允许单个分段覆盖。

统一 `tts_options` 包含：

- `speed_level`：`very_slow/slow/normal/fast/very_fast`。
- `volume_ratio`：仅豆包使用，范围 `0.5–2.0`。
- `style_prompt`：MiMo 预置与克隆使用，最长 300 字。

豆包五档语速分别映射为 `0.8/1.0/1.25/1.5/1.75`，保留当前 `1.25` 的默认节奏。MiMo 将五档语速转换为自然语言节奏指令；`normal` 不额外追加语速指令。

任务创建时将最终解析后的统一音色 ID 和 `tts_options` 快照入库，以后修改全局配置不改变旧任务。分段重配音同时记录该分段实际使用的音色和参数，便于页面回显和重建草稿。

## API 设计

音色目录与试听：

- `GET /ai/native/video/kepu/voices?provider=&include_disabled=`：创作端默认只返回已开放且就绪的音色，配置页可读取全部。
- `PUT /ai/native/video/kepu/voices/availability`：批量保存预置音色的开放状态和两家默认音色。
- `POST /ai/native/video/kepu/voices/preview`：接收 `voice_type`、试听文本、`tts_options` 和可选的未保存 TTS 表单配置，返回本地媒体 URL 与缓存命中状态。

MiMo 克隆音色：

- `GET /ai/native/video/kepu/voice-clones?include_hidden=`：返回本地克隆音色及状态。
- `POST /ai/native/video/kepu/voice-clones`：使用 multipart 接收名称、授权确认和参考音频，创建 `draft`记录。
- `POST /ai/native/video/kepu/voice-clones/{clone_id}/preview`：生成或重新生成克隆试听，成功后将状态改为 `ready`。
- `PATCH /ai/native/video/kepu/voice-clones/{clone_id}`：处理重命名和启用/隐藏。
- `PUT /ai/native/video/kepu/voice-clones/{clone_id}/reference`：替换参考音频并重置验证状态。
- `DELETE /ai/native/video/kepu/voice-clones/{clone_id}`：无引用时删除记录和本地文件；存在旧任务引用时改为 `hidden`并返回保留原因。

任务接口：

- `POST /tasks` 和图片任务创建接口保留 `voice_type`，增加可选 `tts_options`。
- 分段重配音接口使用 `{voice_type, tts_options}` JSON，并兼容现有 `voice_type` query 参数。
- 任务和分段查询返回实际使用的音色和参数快照。

## 删除、隐私与资产保护

克隆音色被关闭或隐藏后只从新任务选择器消失，旧任务、已生成音频和素材记录继续可见。只有 `tasks`、`task_segments` 和 `task_assets` 都不再引用该 `clone_id` 时，才允许彻底删除参考音频。

克隆生成失败时，参考音频、名称和错误信息仍然入库，状态为 `failed`或 `draft`，用户可在修复 MiMo 配置后重试。任何失败不得清空已有试听或任务音频。

参考音频和试听文件只保存在本地媒体目录。后端日志禁止输出 Base64、DataURL、API Key 或原始音频内容。

## 错误处理

- 供应商未启用、配置不完整或选中音色不存在时，在任务提交前返回明确验证错误，不静默切换供应商。
- 已禁用的预置或克隆音色不允许新任务选择，但旧任务可继续基于快照重试。
- 参考音频文件不存在或无法读取时，克隆音色标记为不可用，已生成的任务音频仍保留。
- MiMo 返回空音频、非法 Base64、429 或超时时，沿用现有重试逻辑并将最终错误保存到克隆音色或分段资产记录。
- 试听请求失败不修改当前音色开放状态，前端允许原地重试。

## 测试设计

### 后端单元与集成测试

- SQLite 迁移保留 10 个豆包音色，加入 9 个 MiMo 预置音色，并得到约定的 6 个默认开放音色。
- 统一音色 ID、旧 `voice_type` 兼容和逐次供应商路由正确。
- 豆包数值语速、MiMo 自然语言语速和克隆模型请求体正确。
- 上传 MP3/WAV 和浏览器 WebM 录音后能生成规范 WAV，超过 10 MB、没有音轨或无法解码的文件被拒绝。
- 克隆试听成功后从 `draft` 转为 `ready`，失败时保留参考音频和错误。
- 替换参考音频会使旧试听失效；被任务引用的克隆音色只隐藏，无引用时可彻底删除。
- 任务恢复、失败和资产记录保留统一音色 ID、`tts_options` 和克隆引用。

### 前端测试

- 两家供应商配置同时保留，一家的表单操作不会覆盖另一家。
- 音色筛选、批量启用、默认音色约束和任务覆盖 payload 正确。
- 音色卡点击只播放一条试听，试听失败不改变选中状态。
- 麦克风权限拒绝、录音停止、重录、上传替换和授权确认状态正确。
- `draft/failed/ready/hidden` 克隆音色在配置页和创作端的显示边界正确。

### 真实流程验收

1. 用已生成的本地测试 WAV 作为非个人数据参考音频，创建一个 MiMo 克隆音色并生成试听。
2. 对一个 MiMo 预置音色和一个豆包音色分别生成试听，使用 `ffprobe` 确认三个输出均为有效音频。
3. 创建一个使用 MiMo 克隆音色的短任务，再将其中一个分段用豆包音色重配，确认数据库、素材库、预览页和媒体 URL 一致。
4. 重启前后端后再次打开克隆音色和旧任务，确认参考音频、试听、任务快照和已生成资产未丢失。

## 文档与非目标

实施时同步修改 `AGENTS.md` 和 `CLAUDE.md`，说明统一音色 ID、MiMo 克隆模型、本地参考音频、10 MB 限制、DataURL 不持久化和资产保护规则，两份文档内容必须保持一致。

本期不实现：

- 豆包远端音色同步和 AK/SK 配置。
- 豆包声音复刻、SpeakerID 训练、购买或激活流程。
- MiMo `voicedesign` 文本音色设计和唱歌模式。
- 远程存储、云端音色库或多用户权限系统。
